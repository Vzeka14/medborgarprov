# Övningsprov · medborgarskapsprovet i samhällskunskap

Бесплатный тренажёр для подготовки к шведскому экзамену по обществознанию
(medborgarskapsprovet). Вопросы на шведском с русским переводом, построены по
официальному учебному материалу UHR **«Sverige i fokus»**.

> **Это не официальный тест.** Сайт сделан частным лицом и не связан с UHR,
> Migrationsverket или другим ведомством. UHR не публиковал старых вариантов теста,
> и никто вне ведомства не знает точных вопросов.

## Что известно о реальном тесте

Источник — [uhr.se/medborgarskapsprovet](https://www.uhr.se/medborgarskapsprovet/om-medborgarskapsprovet/) (обновлено 7 июля 2026):

| | |
|---|---|
| Вопросов | около 60, с четырьмя вариантами, верен один |
| Время | 90 минут |
| Язык | шведский |
| Формат | на бумаге |
| Первый тест | 15 августа 2026, Stockholmsmässan |
| Проходной балл | **не опубликован UHR** |

Тест в августе 2026 — `utprövningsprov`, то есть первое реальное применение вопросов
и калибровка сложности. Поэтому проходной балл в приложении задаётся вручную, а не
вшит как факт. Цифра 52, которая ходит по интернету, ничем официально не подтверждена.

## Как это работает

Не «30 фиксированных вариантов», а **банк вопросов + генератор**. Каждая варианта
собирается из банка пропорционально объёму глав в брошюре, варианты ответов
перемешиваются. Код варианта (`K3F9A`) — это сид: одинаковый код всегда даёт
одинаковый тест, поэтому вариантом можно поделиться.

Разбор ошибок показывает главу и страницу «Sverige i fokus», откуда взят факт, плюс
пояснение на русском.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # собирает в dist/
```

`npm run bank` склеивает `data/questions-*.json` в `src/data/questions.json`
и проверяет банк на дубликаты id, число вариантов и корректность индекса ответа.
Этот шаг запускается автоматически перед `dev` и `build`.

## Деплой на GitHub Pages

1. Создать репозиторий `medborgarprov`, запушить в `main`.
2. Settings → Pages → Source → **GitHub Actions**.
3. Всё. Workflow в `.github/workflows/deploy.yml` соберёт и опубликует.

Если репозиторий называется иначе — поменять `VITE_BASE` в workflow и в `vite.config.js`.
Для `имя.github.io` или своего домена ставится `/`.

## Как добавлять вопросы

Это спецификация формата — на неё ссылаются промты генерации вопросов.
Описывает то, что **реально** проверяет `scripts/build-bank.mjs` и что
**реально** использует движок (`src/lib/exam.js`) для банка гражданства
(`data/medborgarskap/`) — не идеализированную схему. У jägarexamen формат
совпадает не во всём — расхождения перечислены отдельно, в конце раздела,
и в этом шаге **не** устранены.

### Файлы

- `data/<exam-id>/questions-*.json` — любое число файлов-массивов вопросов.
  Имя файла ни на что не влияет (сборщик просто читает всё, что подходит
  под `questions-*.json`, и порядок файлов не важен — движок канонизирует
  банк по `id`, `canonicalBank` в `src/lib/exam.js`).
- `data/<exam-id>/why-<lang>.json` — объект `{ "<id вопроса>": "текст
  объяснения" }`, один файл на язык, для каждого языка из
  `requiredLangs`, **кроме одного** — см. «Объяснения» ниже.

### Поля объекта вопроса

| Поле | Обязательно | Описание |
|---|---|---|
| `id` | да | Уникальная строка (сборщик проверяет только уникальность, не формат). У гражданства — конвенция `c<номер главы>-<NN>` (`c5-11`, `NN` с ведущим нулём, отдельная нумерация в каждой главе, см. `data/medborgarskap/questions-*.json`). |
| `ch` | да | Глава — ключ, по которому движок группирует вопросы (`chKey()` в `src/lib/exam.js`, сравнение через `String()`, тип не важен). Должен совпадать с одним из `chapters[].ch` в конфиге экзамена. Сборщик **не проверяет** это совпадение — несуществующий `ch` просто не попадёт ни в одну главу при генерации, без ошибки сборки. |
| `kind` | нет | Не проверяется сборщиком, не используется движком — только для статистики в выводе `npm run bank` (`per typ`). В банке гражданства встречаются `fakta`/`förståelse`/`situation` (см. «Типы вопросов» ниже) — это не закрытый список, проверки на конкретные значения нет. |
| `ref` | да | Ссылка на источник (глава+страница брошюры). Используется в рантайме: показывается в UI под вопросом (`Practice`/`Result`) и группирует ошибки в `refBreakdown()` (движок) для списка «слабых мест» после тренировки по главе. |
| `sv`, `ru`, `en`, `ar` | по одному объекту на каждый язык из `requiredLangs` экзамена | `{ "q": "текст вопроса", "o": ["A","B","C","D"] }` — ровно 4 варианта (сборщик проверяет `o.length === 4`), один и тот же порядок вариантов для всех языков одного вопроса (движок перемешивает индексы один раз и применяет ко всем языкам синхронно, `shuffleOptions` в `src/lib/exam.js`). |
| `correct` | да | Индекс верного варианта в ИСХОДНОМ порядке (до перемешивания), целое 0–3. |
| `why` | да, **только если `'ru'` есть в `requiredLangs`** | Объяснение на русском, встроено прямо в объект вопроса — единственный язык объяснения, для которого нет отдельного файла (см. «Объяснения» ниже). |

`order` в вопрос никогда не пишется руками — его добавляет движок в рантайме (`shuffleOptions`), это результат перемешивания, не часть авторского формата.

### Объяснения (`why*`): поле `why` против файлов `why-<lang>.json`

`scripts/build-bank.mjs` жёстко (константа `EMBEDDED_WHY_LANG = 'ru'`, **не
берётся из конфига экзамена**) считает русский тем единственным языком
объяснения, который лежит прямо в вопросе, полем `why`. Так сложилось
исторически — при разработке банка гражданства русское объяснение
появилось раньше остальных и осталось в самом вопросе, а sv/en/ar
объяснения добавлялись позже и легли в отдельные файлы:

- `why` (в самом вопросе) → русское объяснение, попадает в `q.why` как есть.
- `data/<exam-id>/why-sv.json` → шведское, попадает в поле `q.whySv`.
- `data/<exam-id>/why-en.json` → английское, попадает в поле `q.whyEn`.
- `data/<exam-id>/why-ar.json` → арабское, попадает в поле `q.whyAr`.

Правило поля: `whyField(lang) = lang === 'ru' ? 'why' : 'why' + Lang` (первая
буква языка — заглавная). Сборщик требует файл `why-<lang>.json` для
**каждого** языка из `requiredLangs`, кроме `'ru'` (если он там есть).

**Для jägarexamen `'ru'` не входит в `requiredLangs` (там только `'sv'`)** —
значит embedded-поле `why` вообще не нужно и не проверяется, а шведское
объяснение обязано идти через файл `data/jagarexamen/why-sv.json`
(единственный требуемый язык объяснения там — не «нулевой» случай, а
самый обычный: он просто не является тем единственным языком, для
которого сборщик делает исключение).

### Типы вопросов (`kind`) в текущем банке

Неформальная категоризация, не проверяется кодом:

- `fakta` — знание факта («сколько лен в Швеции»).
- `förståelse` — понимание («почему устроено именно так»).
- `situation` — применение к ситуации/кейсу («что сделать, если...»).

### Пример: гражданство (`data/medborgarskap/`)

Реальный вопрос из банка (`c1-01`), плюс соответствующие строки из файлов
объяснений — ровно то, что действительно лежит в репозитории:

```json
{
  "id": "c1-01",
  "ch": 1,
  "kind": "fakta",
  "ref": "Landet Sverige, s. 5",
  "sv": { "q": "Vilken är Sveriges nordligaste punkt?", "o": ["Smygehuk", "Kebnekaise", "Treriksröset", "Malmberget"] },
  "ru": { "q": "Какая точка является самой северной в Швеции?", "o": ["Смюгехук", "Кебнекайсе", "Трериксрёсет", "Мальмбергет"] },
  "en": { "q": "Which is Sweden's northernmost point?", "o": ["Smygehuk", "Kebnekaise", "Treriksröset", "Malmberget"] },
  "ar": { "q": "ما هي أقصى نقطة في شمال السويد؟", "o": ["سميوغهوك", "كبنكايسه", "تريريكسروسيت", "مالمبرييت"] },
  "correct": 2,
  "why": "Швеция вытянута примерно на 1600 км от Трериксрёсета на севере до Смюгехука на юге."
}
```

`data/medborgarskap/why-sv.json`: `"c1-01": "Sverige sträcker sig cirka 1 600 km från Treriksröset i norr till Smygehuk i söder."`
(аналогично `why-en.json`/`why-ar.json` под тем же id).

### Пример: jägarexamen (иллюстративный — таких вопросов ещё нет в банке)

`requiredLangs: ['sv']` — значит `ru`/`en`/`ar`-объекты необязательны,
`why` (встроенное поле) не нужен, объяснение только через
`why-sv.json`:

```json
{
  "id": "artkannedom-01",
  "ch": "artkannedom",
  "kind": "fakta",
  "ref": "Kompetensbeskrivning, Område 1",
  "sv": { "q": "Exempel på frågetext?", "o": ["A", "B", "C", "D"] },
  "correct": 0
}
```

`data/jagarexamen/why-sv.json`: `"artkannedom-01": "Exempel på förklaringstext."`

`id` `artkannedom-01` следует конвенции `<ch>-<NN>` по аналогии с
гражданством (`c<номер>-<NN>`) — источники (`docs/jagarexamen-regler.md`,
`docs/jagarexamen-struktur.md`) сами такую конвенцию не задают, это
предложенное продолжение существующего паттерна, не факт из документов.

### Где формат гражданства не подходит jägarexamen (не исправлено в этом шаге)

1. **`shuffleOptions()` в `src/lib/exam.js` жёстко ждёт все четыре поля
   `sv`/`ru`/`en`/`ar`** (`src/lib/exam.js:56-59`) — это ОБЩИЙ движок, не
   код конкретного экзамена. Вопрос jägarexamen без `ru`/`en`/`ar`
   (легальный по `requiredLangs: ['sv']`, сборщик его пропустит) уронит
   генерацию экзамена в рантайме с `TypeError` на `q.ru.o`, как только в
   банке появится хотя бы один такой вопрос и кто-то попробует
   сгенерировать тест/тренировку. Сборка (`npm run bank`) это не поймает
   — упадёт только рантайм.
2. **Embedded-`why`-язык (`ru`) захардкожен в самом сборщике
   (`scripts/build-bank.mjs`, `EMBEDDED_WHY_LANG`), не в конфиге
   экзамена.** Для jägarexamen это не имеет эффекта (там нет `ru`), но
   если у jägarexamen когда-нибудь появится `ru` как требуемый язык,
   встроенное поле `why` при этом станет означать «русское объяснение»
   так же, как у гражданства — этот выбор нельзя переопределить per-экзамен
   без правки самого сборщика.
3. **Конвенция `id`/`ch` гражданства предполагает числовую главу** (`c5-11`
   при `ch: 5`). У jägarexamen `ch` — строковый слаг; предложенная выше
   аналогия `<ch>-<NN>` — моё предложение по образцу, не требование
   источников.
4. **`optionsPerQuestion` — тут формат СОВПАДАЕТ, не расхождение:**
   ровно 4 варианта ответа зашито и в движке (`LETTER = ['A','B','C','D']`
   в UI, диапазон `correct` 0–3 в `scripts/build-bank.mjs`), и в самом
   jägarexamen по источнику (JPM, §5.2.2 — «fyra svarsalternativ»,
   см. `docs/jagarexamen-regler.md`). Явно отмечено, чтобы не выглядело
   пропущенным.
5. **`config.examLanguages` (языки сдачи настоящего экзамена, `['sv','en']`
   у jägarexamen) сейчас нигде не читается кодом** — ни движком, ни
   сборщиком. Это описательное поле конфига на будущее, не подключено ни
   к чему в этом шаге.

Правила содержания (не копировать дословно из источника, правдоподобные
дистракторы, доля `situation`-вопросов и т.д. — см. коммиты банка
гражданства) — про сам текст вопросов, а не про формат данных, здесь
намеренно не повторяются.

## Состояние банка

100 вопросов, все 13 глав. Цель — 400–500. Из брошюры на 47 страниц больше
качественных непересекающихся вопросов не выжать; всё сверх этого начнёт
повторяться и обесценит тренажёр.
